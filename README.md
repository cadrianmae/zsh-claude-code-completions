# zsh-claude-code-completions

Zsh tab completion for the [Claude Code](https://claude.com/claude-code) CLI,
generated by parsing `claude --help` — no AI in the loop, no API key, no
network access.

```
$ claude --permission-mode <TAB>
acceptEdits  auto  bypassPermissions  dontAsk  manual  plan

$ claude plugin <TAB>
details    -- Show a plugin's component inventory and projected token cost
disable    -- Disable an enabled plugin
enable     -- Enable a disabled plugin
...
```

Covers every option and every subcommand the CLI reports, three levels deep,
with real value completion wherever the CLI declares its choices.

## Install

**oh-my-zsh**

```bash
git clone https://github.com/cadrianmae/zsh-claude-code-completions \
  ~/.oh-my-zsh/custom/plugins/zsh-claude-code-completions
```

Add it to `plugins=(...)` in `~/.zshrc`, then `exec zsh`.

**Manual**

```bash
git clone https://github.com/cadrianmae/zsh-claude-code-completions
cd zsh-claude-code-completions
just install   # symlinks _claude into ~/.zsh/completions
```

Ensure the directory is on `$fpath` *before* `compinit` runs:

```zsh
fpath=(~/.zsh/completions $fpath)
autoload -Uz compinit && compinit
```

If tab does nothing after installing, the completion cache is stale:
`rm -f ~/.zcompdump*; exec zsh`.

## Keeping it current

The CLI ships often. Check and rebuild against your installed binary:

```bash
just staleness   # is _claude behind?
just build       # regenerate + verify
```

Generation takes about fifteen seconds and needs only the `claude` binary on
`$PATH`.

## How it works

The CLI is built on [commander.js](https://github.com/tj/commander.js), whose
`--help` output is regular enough to parse mechanically:

- an `Options:` block, one entry per flag, with metavariables (`<dir>`,
  `[filter]`, `<files...>`) that reveal whether an argument is required and
  whether it repeats;
- a `Commands:` block, which `bin/gen-completion` walks recursively by
  invoking `claude <cmd> --help` for each entry;
- inline value constraints spelled `(choices: "a", "b")`, which become real
  zsh completion candidates.

One wrinkle drives the design. Commander wraps help text to the terminal
width, and when stdout is not a TTY it ignores `$COLUMNS` and hard-wraps at
80 columns — descriptions straddle several lines and flag specs turn
ambiguous. The generator therefore runs the CLI under a pty sized to 400
columns, so every entry stays on one line and the grammar stays simple.

### What `--help` cannot tell us

Some options document their values in prose rather than commander's machine
-readable form — `--model` and `--effort` among them — and some values are
not static at all. Two files fill those gaps:

- **`overrides.json`** — literal choices or completion actions, keyed by flag
  name and optionally qualified by command path.
- **`helpers.zsh`** — zsh functions inlined into the output, completing from
  your own Claude Code state: `--agent` from `.claude/agents/`, `--resume`
  from the transcripts of the current project directory (newest first),
  `--marketplace` from installed marketplaces.

Both are hand-maintained, and deliberately conservative: offering no
completion is a smaller lie than offering a wrong one.

## Verifying

`just verify` does more than a syntax check. It starts a real interactive zsh
over a `zpty`, types a prefix, presses tab, and asserts on what came back —
so a completion that parses but never fires still fails the build. Eighteen
checks cover static structure, command aliases, override-supplied values, and
the dynamic helpers.

Checks against machine-specific state derive their expected value from that
same state, and skip when the machine has none, rather than hard-coding a
name that only exists on one laptop.

This suite earns its keep. An earlier revision named a helper `_claude_agents`,
which the `claude agents` subcommand's own generated completer silently
overwrote — turning `claude --agent <TAB>` into unbounded recursion
(`_tags: job table full or recursion limit exceeded`). It parsed fine and the
static checks were green. Only pressing tab found it. The generator now
refuses to emit when a helper name collides with a generated one.

## Layout

| Path                 | Purpose                                       |
| -------------------- | --------------------------------------------- |
| `bin/gen-completion` | The generator                                 |
| `_claude`            | Generated completion (committed)              |
| `claude-version`     | CLI version `_claude` was built from          |
| `overrides.json`     | Hand-maintained choices and actions           |
| `helpers.zsh`        | Dynamic completion functions                  |
| `scripts/verify.sh`  | Syntax and behaviour checks                   |

## Prior art

Other takes on the same problem, which differ mainly in how the script is
produced and maintained:

- [wbingli/zsh-claudecode-completion](https://github.com/wbingli/zsh-claudecode-completion)
  — regenerates by running Claude Code itself in a daily GitHub Action.
- [itsdevcoffee/claude-code-zsh](https://github.com/itsdevcoffee/claude-code-zsh)
  — hand-written, broad flag coverage.
- [hmmf022/cc-completion](https://github.com/hmmf022/cc-completion)
  — bash, zsh, and nushell.
